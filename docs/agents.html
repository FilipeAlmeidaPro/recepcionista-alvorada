Who checks whom

The cast of Voice Agent Assistant: nine agents, five models, four surfaces. Five use an LLM. The supervisor that coordinates those five does not — it's code.

The cast at work

On a call, the orchestrator is the only one holding tools — and the only one that can invent. Everything around it is code that doesn't: one hands over what was said, already normalised; another checks what it wants to write; another measures what happened.

It's almost always the one speaking, too. The exception is the only one that matters: the sentence that escalates a clinical risk comes from the supervisor, in code.

Supervision runs alongside, not in front

The common multi-agent pattern is an LLM supervisor that reads the turn and decides which specialist to route to. Here that would cost one network hop per turn in a system already 3.5× over its latency target — to decide something an if decides better, in zero milliseconds.

So the supervisor is code, and the specialist runs in parallel: as long as it's faster than the orchestrator, it never shows up on the turn's bill.

The hypothesis that justified this layer was wrong. I wrote that the orchestrator, busy booking, would miss a signal buried mid-sentence. I measured it, and it doesn't: 120b caught it on its own, and 20b caught 4 out of 4.

What the measurement did show is smaller and true — a specialised classifier beats a busy generalist on precision. The guardian scored 7/7; the cheap orchestrator scored 6/7, escalating a chest pain from last year, already investigated, which the guardian correctly declined. In no measured case did the guardian catch something the orchestrator missed.

What has run, and what hasn't

The suite is a matrix: who answers on one axis, who calls on the other. Each can be an LLM or a script. One of the four cells is empty — and it's exactly the one the README calls most important.

No LLM is required to run the project. With no key at all: 213 tests pass, the 40 scenarios run against the rule-based baseline, and the entity benchmark compares regex against the normalizer. The LLM is there to measure the model, not to make the system work.

The count that matters: five of the nine agents use an LLM. The other four — supervisor, validator, judge, baseline — coordinate and check with no model at all. Add the normalizer and the VAD, and the ratio becomes five that can be wrong against six that check.

And the most telling part: the agent that coordinates the five LLM-powered ones is the one without an LLM.

It's the project's thesis said another way: the model proposes, the code writes. The org chart is the architecture.
